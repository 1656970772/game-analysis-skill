# GameAnalysis Unity 动态特效预览工具设计

日期：2026-06-16

## 背景

GameAnalysis 已有图片画廊和模型预览工具，交付方式都是 Skill 级固定 EXE、每个 study-root 的 BAT 入口、项目 manifest 和临时索引目录。现有 VFX 链路只有 `build_vfx_preview_manifest.py`，它能把 `ParticleSystem`、`ParticleSystemRenderer`、`TrailRenderer`、`LineRenderer`、材质、贴图、mesh、动画等资源分类成配置卡和资源关联，但不能动态播放特效，也不能生成可重新导入 Unity 的工程片段。

本设计将 VFX 链路升级为 Unity 动态特效重建工具。第一版只支持 Unity，目标是把已授权本地导出的 Unity VFX 资源转成可预览、可复核、可回导 Unity 的中间产物，而不是只展示粒子贴图。

## 目标

- 在 Skill 中维护固定 `GameVfxViewer.exe`，每个 study-root 只生成 `2.报告/打开特效预览.bat` 作为入口。
- 生成 `4.临时目录/中间索引/VFX预览/manifest.json`、`errors.jsonl`、`reconstructed/`、`unity-export/` 和 `preview-cache/`。
- 第一版从 UnityPy 全量可读资源索引中解析 Unity VFX 组件：`ParticleSystem`、`ParticleSystemRenderer`、`TrailRenderer`、`LineRenderer`、`Material`、`Texture2D`、`Sprite`、`Mesh`、`AnimationClip`。AssetRipper 输入只作为后续 adapter 扩展，不进入第一版验收。
- 将 Unity 粒子模块归一化为配置化 schema，覆盖第一版可复现的核心模块：duration、looping、start lifetime、start speed、start size、start color、emission、shape、velocity over lifetime、color over lifetime、size over lifetime、texture sheet animation、renderer material、render mode、sorting、trail/line width/color/material。
- `GameVfxViewer.exe` 使用 manifest 动态播放重建特效，支持列表筛选、播放/暂停、重播、速度、背景切换、时间轴、资源详情、打开目录和错误提示。
- 同步生成 Unity 可回导工程片段，默认位置为 `4.临时目录/中间索引/VFX预览/unity-export/Assets/GameAnalysisVfxPreview/`，包含 prefab、material、texture、mesh、animation 和生成脚本；可由用户复制或导入到对应 Unity 工程复核。
- 在 `2.报告/00_研究总览.md` 写入特效预览摘要，区分可动态重建、部分重建、仅资源关联、失败的数量。
- 遵守授权边界：只读取 study-root 内的授权导出资源，不联网、不上传、不修改源游戏目录，不把固定 EXE 复制进每个项目。

## 非目标

- 第一版不实现 Unreal、Cocos、Godot 或自研引擎的动态特效重建，只保留 adapter 接口和 manifest 字段。
- 第一版不承诺 100% 还原 Unity runtime 行为；sub emitter、collision、trigger、noise、external forces、custom shader graph、脚本驱动参数和项目运行时代码只记录为 `unsupported_modules`。
- 第一版不编辑原始游戏资源，不回写 `1.分类资源/特效/` 下的原文件。
- 第一版不自动打开 Unity Editor，也不要求每次分析都安装 Unity；回导产物以文件系统工程片段为主。
- 第一版不把 VFX 资源打包成可分发素材包；它只用于本地学习、复核和回导验证。

## 推荐架构

采用“Unity VFX adapter + 固定 Electron/Three.js 预览器 + Unity 回导生成器”的架构：

```text
game-analysis/
  assets/
    vfx-viewer-src/
      package.json
      main.js
      preload.js
      renderer/
        index.html
        renderer.js
        styles.css
  built-in-tools/
    GameVfxViewer_1.0.0/
      GameVfxViewer.exe
      VERSION.txt
      LICENSES/
  references/
    vfx-preview-config.json
    vfx-unity-reconstruction-schema.json
  scripts/
    vfx_preview_common.py
    build_vfx_preview_manifest.py
    export_unity_vfx_reconstruction.py
    create_vfx_viewer_launcher.py
    update_vfx_preview_summary.py
    build_vfx_viewer_tool.ps1
    verify_vfx_viewer_gui.ps1

<study-root>/
  2.报告/
    打开特效预览.bat
  4.临时目录/
    中间索引/
      VFX预览/
        manifest.json
        errors.jsonl
        reconstructed/
          <effect-id>.json
        preview-cache/
        unity-export/
          Assets/
            GameAnalysisVfxPreview/
```

`build_vfx_preview_manifest.py` 负责发现候选特效、建立对象关联和写 manifest；`export_unity_vfx_reconstruction.py` 负责把 manifest 中的 Unity VFX 记录转换为 Three.js 播放用 reconstruction JSON 和 Unity 回导工程片段；`GameVfxViewer.exe` 只读加载 manifest 和 reconstruction JSON，提供动态预览。

## 数据流

1. Unity 资源导出完成后，`build_vfx_preview_manifest.py --study-root "<study-root>" --skill-root "<skill-root>"` 读取 UnityPy 全量索引和 `references/vfx-preview-config.json`。第一版不读取 AssetRipper 工程目录。
2. 脚本按配置化规则识别特效根对象，优先以 `ParticleSystem`、`TrailRenderer`、`LineRenderer` 为动态预览入口，再关联 renderer、material、texture、mesh 和 animation。
3. 脚本写入 `manifest.json`，每个 item 标记 `engine: "unity"`、`preview_status`、`reconstruction_status`、`unity_export_status`、`supported_modules`、`unsupported_modules`、`source_refs`、`dependencies` 和 `warnings`。
4. `export_unity_vfx_reconstruction.py` 读取 manifest，为每个可重建 item 写入 `reconstructed/<effect-id>.json`，并生成 `unity-export/Assets/GameAnalysisVfxPreview/` 下的 Unity 工程片段。
5. `create_vfx_viewer_launcher.py` 生成 `2.报告/打开特效预览.bat`，BAT 传入 `--study-root`、`--manifest`、`--reconstructed-dir`、`--preview-cache-dir`、`--unity-export-dir`。
6. `update_vfx_preview_summary.py` 更新 `2.报告/00_研究总览.md` 中的特效预览摘要。
7. 完成前运行 `GameVfxViewer.exe --self-test ...` 和 `verify_vfx_viewer_gui.ps1`，验证列表、canvas、播放控制、时间轴、资源详情、Unity 回导目录按钮和错误提示。

## Manifest 设计

manifest 必须稳定、可扩展、配置化，不写死游戏名、path id 或某次任务目录：

```json
{
  "schema_version": 1,
  "generated_at": "2026-06-16T00:00:00Z",
  "study_root": "E:\\AI_Projects\\GameAnalysis\\ExampleGame",
  "viewer": {
    "required_tool": "GameVfxViewer",
    "minimum_version": "1.0.0"
  },
  "items": [
    {
      "id": "stable-effect-id",
      "engine": "unity",
      "name": "fire_loop",
      "kind": "particle_system",
      "preview_status": "ready",
      "reconstruction_status": "full",
      "unity_export_status": "ready",
      "reconstruction_path": "E:\\...\\VFX预览\\reconstructed\\stable-effect-id.json",
      "unity_export_path": "E:\\...\\VFX预览\\unity-export\\Assets\\GameAnalysisVfxPreview\\Prefabs\\fire_loop.prefab",
      "source_refs": [
        {
          "asset_type": "ParticleSystem",
          "source_file": "resources.assets",
          "path_id": "100",
          "export_path": "metadata/ParticleSystem/fire_loop.json"
        }
      ],
      "dependencies": {
        "materials": [],
        "textures": [],
        "meshes": [],
        "animations": []
      },
      "supported_modules": ["main", "emission", "shape", "renderer"],
      "unsupported_modules": ["sub_emitters"],
      "warnings": []
    }
  ]
}
```

`preview_status` 可取 `ready`、`partial`、`resource_only`、`failed`、`unsupported`。`reconstruction_status` 可取 `full`、`partial`、`resource_only`、`failed`。`unity_export_status` 可取 `ready`、`partial`、`skipped`、`failed`。

## Unity 重建 Schema

`reconstructed/<effect-id>.json` 使用配置化 schema 表达可播放参数。第一版字段围绕 Unity 粒子常用模块设计：

- `main`：duration、looping、prewarm、startDelay、startLifetime、startSpeed、startSize、startRotation、startColor、gravityModifier、simulationSpace、scalingMode、maxParticles。
- `emission`：rateOverTime、rateOverDistance、bursts。
- `shape`：shapeType、angle、radius、radiusThickness、arc、box、meshRef。
- `velocityOverLifetime`：enabled、linear、orbital、speedModifier。
- `colorOverLifetime`：enabled、gradient keys。
- `sizeOverLifetime`：enabled、curve。
- `textureSheetAnimation`：enabled、tiles、animation、frameOverTime、startFrame、cycles。
- `renderer`：renderMode、materialRef、meshRef、sortingLayer、sortingOrder、alignment、flip、minParticleSize、maxParticleSize。
- `trail` / `line`：widthCurve、colorGradient、materialRef、textureMode、alignment。

未知或不支持字段不丢弃，写入 `raw_unity` 和 `unsupported_modules`，用于报告和后续迭代。

## 预览器设计

`GameVfxViewer.exe` 采用 Electron 壳，renderer 使用 Three.js 和自定义 particle runtime。第一版 runtime 支持 billboard 粒子、mesh 粒子、trail/line ribbon、texture sheet animation、颜色/尺寸/速度曲线、loop 和 burst。UI 保持工具型界面：

- 左侧：特效列表、搜索、状态筛选、标签筛选。
- 中央：动态 canvas，支持播放、暂停、重播、速度、背景色/棋盘格、相机重置。
- 底部：时间轴、当前时间、duration、loop 状态。
- 右侧：源对象、依赖资源、支持/不支持模块、Unity 回导路径、打开目录按钮。
- 自测：`--self-test` 必须验证 manifest 可读、至少一个 item 可加载、canvas 非空、播放时间推进、错误区无 fatal。

## Unity 回导产物

回导目录固定在 `4.临时目录/中间索引/VFX预览/unity-export/Assets/GameAnalysisVfxPreview/`。生成内容按配置化目录组织：

```text
Assets/GameAnalysisVfxPreview/
  Prefabs/
    <effect-name>.prefab
  Materials/
    <material-name>.mat
  Textures/
    <texture-files>
  Meshes/
    <mesh-files>
  Animations/
    <animation-files>
  Scripts/
    GameAnalysisVfxBootstrap.cs
  Metadata/
    <effect-id>.json
```

Unity 回导采用文本 prefab/material/meta 片段和 Bootstrap 脚本组合。对于 Unity 原始 YAML 无法安全还原的字段，用 `Metadata/<effect-id>.json` 保留原始值，由 `GameAnalysisVfxBootstrap.cs` 在 Editor 或 Play 模式中按 JSON 设置 ParticleSystem 参数。脚本只引用当前回导目录内资源，不引用源游戏路径。

## 错误处理与边界

- 缺失贴图、材质、mesh 或 animation 时，item 降级为 `partial`，并写入 `errors.jsonl` 和 item `warnings`。
- 遇到不支持模块时，不阻塞同一个特效的基础播放；`unsupported_modules` 必须清楚列出。
- 找不到 UnityPy 索引时，脚本输出空 manifest 和 warning，不影响图片、模型、代码、报告流程；AssetRipper 索引缺失不影响第一版。
- BAT 只启动固定 EXE，不执行导入 Unity、不提升权限、不联网。
- 所有路径必须在 study-root 或 Skill root 内；配置路径越界时直接失败。

## 测试策略

- Python 单元测试覆盖配置读取、路径越界保护、Unity VFX 行识别、依赖关联、manifest 状态、reconstruction JSON 输出、Unity 回导目录生成、BAT 内容。
- Electron 自测覆盖 manifest 参数、reconstruction 加载、canvas 非空、播放推进、错误状态和打开目录按钮存在。
- GUI 验证脚本通过 Electron CDP 验证列表渲染、播放/暂停、时间轴拖动、速度调整和 Unity 回导路径展示。
- 回归测试继续运行 `scripts/run_skill_tests.ps1`，确保图片、模型和现有 GameAnalysis 流程不被破坏。

## 实施验收

- `references/vfx-preview-config.json` 不再把第一版 VFX 预览定义为配置卡终态，而是配置 Unity adapter、模块支持矩阵、路径、状态枚举和导出目录。
- `scripts/build_vfx_preview_manifest.py` 仍保留分类和资源关联能力，但 manifest 必须能驱动动态重建。
- 新增 `scripts/export_unity_vfx_reconstruction.py`、`scripts/create_vfx_viewer_launcher.py`、`scripts/update_vfx_preview_summary.py`、`scripts/build_vfx_viewer_tool.ps1`、`scripts/verify_vfx_viewer_gui.ps1`。
- 新增 `assets/vfx-viewer-src/` 和固定工具 `built-in-tools/GameVfxViewer_1.0.0/GameVfxViewer.exe`。
- `SKILL.md`、`references/local-export-preview-requirements.md`、`references/directory-spec.md`、`references/tooling-manifest.json` 和完成前检查都明确特效预览入口、manifest、动态预览、自测和 Unity 回导产物。
- 第一版样例测试中，至少一个 `ParticleSystem` 能从模拟 UnityPy metadata 生成 reconstruction JSON、在 viewer 中播放动态粒子，并生成 Unity 回导目录。

## 计划自审

- 通用架构：采用 engine adapter、manifest、reconstruction schema 和固定 viewer，不针对某个游戏或单个 path id 硬编码。
- 设计模式适配：沿用图片/模型预览的固定 EXE + BAT + manifest 模式；新增 Unity adapter 和 exporter 作为可扩展边界。
- 配置化覆盖范围：路径、状态枚举、支持模块、关键词规则、导出目录、viewer 工具路径、BAT 名称和限制均应放入配置文件。
- 范围控制：第一版只做 Unity 动态预览和 Unity 回导；Unreal/Cocos 不进入实现。
