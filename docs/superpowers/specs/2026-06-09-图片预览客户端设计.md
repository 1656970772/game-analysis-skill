# GameAnalysis 图片预览客户端设计

## 背景

GameAnalysis 现有图片画廊链路由 `scripts/build_full_image_gallery.py` 生成 `2.报告/全量图片画廊.html`，再由 `scripts/build_gallery_exe.ps1` 在每个 study-root 的 `4.临时目录/工具产物/gallery-exe/` 里复制 Electron 模板、执行 `npm install` 和 `npm run dist`，最后把 EXE 复制到 `2.报告/`。

用户确认的新方向是：不再让每次 GameAnalysis 执行都重新生成 HTML 画廊或重新构建 EXE；改为在 Skill 的 `tools/` 目录维护一个固定图片预览客户端 EXE，每个输出项目只生成一个 BAT 启动器，把本次导出的图片目录和 manifest 路径传给固定 EXE。固定 EXE 是本方案的必达交付：如果目标 EXE 已存在则必须验证现有 EXE；如果不存在则必须运行构建脚本生成；Node/npm 不可用且又不能另行提供固定 EXE 时，本任务状态必须标记为 BLOCKED，不能宣称完成。旧 HTML 画廊保留为兼容/应急工具，但不作为默认产物。

## 目标

- 在 `built-in-tools/GameImageGallery_1.0.0/GameImageGallery.exe` 提供固定的离线图片预览客户端，并把该 EXE 的存在验证和 `--self-test` 烟测作为必达验收。
- 在每个 study-root 的 `2.报告/` 下生成 `打开图片画廊.bat`，用户双击即可浏览本次导出的图片。
- 默认关联 `1.分类资源/图片/`，同时允许通过配置或命令行增加原始导出图片根目录。
- 把图片 manifest、缩略图、错误日志和客户端运行所需索引写入 `4.临时目录/中间索引/图片画廊/`。
- 替代默认 HTML 画廊流程；`build_full_image_gallery.py` 和旧 Electron HTML 壳只保留为兼容工具。
- 遵守本地授权边界：只读取用户授权 study-root 内的导出图片，不联网、不上传、不修改源游戏目录。

## 非目标

- 第一版不做图片编辑、批量改名、资源导出打包、标注写回或素材复用。
- 第一版不承诺跨机器移动单个 BAT 后仍可运行；BAT 是当前机器上指向本机 Skill 工具的轻量入口。
- 第一版不删除旧 HTML 脚本，避免破坏已有报告或历史测试；默认 workflow 和文档改为新 BAT 客户端。
- 第一版不内置在线依赖、云预览、账号登录或遥测。

## 方案比较

### 方案 A：继续生成 HTML，BAT 只打开 HTML

优点是改动小，能复用现有 `build_full_image_gallery.py`。缺点是仍然需要为每个项目写完整 HTML，客户端能力受静态页面限制，`打开目录` 按钮、本地文件管理器定位和授权路径校验仍依赖旧 Electron 壳，不能解决“替代现在 HTML 画廊”的核心诉求。

### 方案 B：固定 Electron EXE 读取 manifest

这是推荐方案。Python 负责扫描图片、生成缩略图和 manifest；Electron EXE 只读加载 manifest，通过本地安全协议显示缩略图和原图。每次 GameAnalysis 输出只新增 `打开图片画廊.bat` 和 `4.临时目录/中间索引/图片画廊/` 数据，不再重新 build EXE。

优点是复用 Web UI 生态，适合大量图片检索、筛选、覆盖层预览、`打开目录` 按钮定位、缩放/拖拽预览和后续扩展；也符合现有 Electron 模板经验。缺点是首次沉淀工具时需要一次性构建 EXE，并维护 Node/Electron 源模板。

### 方案 C：原生 Windows/WPF 图片浏览器

优点是依赖少、启动快。缺点是从零维护 UI、缩略图虚拟列表、透明背景预览、中文路径和打包流程成本更高，也不匹配现有 Skill 中已有 Electron 经验。

## 推荐架构

采用“固定工具 EXE + 项目 BAT 启动器 + 项目 manifest”的架构：

```text
game-analysis/
  assets/
    image-gallery-viewer-src/              # 固定 EXE 源模板
      package.json
      main.js
      preload.js
      renderer/
        index.html
        styles.css
        renderer.js
  references/
    image-gallery-viewer-config.json       # 画廊规则配置
    tooling-manifest.json                  # 记录固定 EXE 工具
  scripts/
    image_gallery_common.py                # 配置、路径、hash、manifest 公共逻辑
    build_image_gallery_manifest.py        # 生成图片 manifest 和 PNG 缩略图
    create_image_gallery_launcher.py       # 生成 2.报告/打开图片画廊.bat
    build_image_gallery_viewer_exe.ps1     # 一次性构建固定 EXE 到 tools/
  tools/
    GameImageGallery_1.0.0/
      GameImageGallery.exe
```

每个输出项目只新增：

```text
<study-root>/
  2.报告/
    打开图片画廊.bat
  4.临时目录/
    中间索引/
      图片画廊/
        manifest.json
        errors.jsonl
        thumbnails/
          <stable-id>.png
```

## 数据流

1. GameAnalysis 完成图片导出和分类，确保 `1.分类资源/图片/` 存在。
2. 调用 `build_image_gallery_manifest.py --study-root "<study-root>"`。
3. Manifest 构建器读取 `references/image-gallery-viewer-config.json`，按配置扫描一个或多个图片根目录。
4. 构建器为支持格式生成 PNG 缩略图，写入 `4.临时目录/中间索引/图片画廊/thumbnails/`。
5. 构建器写入 `manifest.json` 和 `errors.jsonl`。
6. 调用 `create_image_gallery_launcher.py --study-root "<study-root>" --skill-root "<skill-root>"`。
7. 启动器脚本读取 manifest 中的 `source_roots`，在 `2.报告/打开图片画廊.bat` 写入固定 EXE 路径、本次 manifest 路径，并用重复 `--images-root` 显式传入每个图片根。
8. 用户双击 BAT，固定 EXE 读取命令行参数，校验 `--images-root` 与 manifest `source_roots` 完全一致后放行，加载 manifest，显示缩略图网格和原图预览。

## BAT 启动器契约

BAT 是本机双击入口，也是 EXE 的显式图片根授权载体。生成器必须从 manifest 的 `source_roots[].path` 派生重复 `--images-root` 参数；manifest 仍是数据契约，BAT 不能绕过 manifest 自行授权额外目录。

```bat
@echo off
chcp 65001 >nul
setlocal
set "STUDY_ROOT=<study-root>"
set "GALLERY_EXE=<skill-root>\built-in-tools\GameImageGallery_1.0.0\GameImageGallery.exe"
set "MANIFEST_PATH=<study-root>\4.临时目录\中间索引\图片画廊\manifest.json"
set "IMAGE_ROOT_1=<study-root>\1.分类资源\图片"

start "" "%GALLERY_EXE%" --study-root "%STUDY_ROOT%" --manifest "%MANIFEST_PATH%" --images-root "%IMAGE_ROOT_1%"
endlocal
```

多个图片根时按 `IMAGE_ROOT_1`、`IMAGE_ROOT_2` 递增，并在启动命令中重复追加 `--images-root "%IMAGE_ROOT_N%"`。

## Manifest 契约

`manifest.json` 是 Python 生成链路和 EXE 运行时之间的唯一数据契约。EXE 不递归扫描磁盘，避免运行时误扫未授权路径。运行时授权必须同时满足两层条件：manifest 声明图片来源，BAT/CLI 用重复 `--images-root` 显式传入同一组图片根；两者规范化后的集合不一致时，EXE 必须拒绝启动。

```json
{
  "schema_version": 1,
  "tool": {
    "name": "GameImageGallery",
    "version": "1.0.0"
  },
  "study_root": "<study-root>",
  "generated_at": "2026-06-09T22:00:00+08:00",
  "title": "<项目名> 图片画廊",
  "source_roots": [
    {
      "label": "分类图片",
      "path": "<study-root>\\1.分类资源\\图片"
    }
  ],
  "items": [
    {
      "id": "sha1-16",
      "name": "icon.png",
      "source_label": "分类图片",
      "source_path": "<study-root>\\1.分类资源\\图片\\UI\\icon.png",
      "relative_path": "UI/icon.png",
      "category": "UI",
      "width": 64,
      "height": 64,
      "mode": "RGBA",
      "has_alpha": true,
      "size_bytes": 2048,
      "modified_time": "2026-06-09T21:50:00+08:00",
      "thumbnail_path": "<study-root>\\4.临时目录\\中间索引\\图片画廊\\thumbnails\\sha1-16.png",
      "status": "ready"
    }
  ],
  "summary": {
    "item_count": 1,
    "failed_count": 0,
    "thumbnail_count_created": 1
  }
}
```

状态枚举集中配置：`ready`、`thumbnail_failed`、`unsupported`、`missing`。

## 客户端能力

- 左侧或顶部工具栏：搜索、分类筛选、来源筛选、排序、每页数量。
- 主区域：稳定尺寸图片卡片网格，显示缩略图、文件名、尺寸、分类和相对路径。
- 覆盖层预览：点击卡片打开预览覆盖层；鼠标滚轮缩放图片；按住鼠标左键拖拽平移图片；预览仅通过右上角 X/关闭按钮或 Esc 关闭。
- 键盘操作：Esc 关闭预览。
- 目录定位：`打开目录` 按钮通过系统文件管理器打开并定位当前图片；右键不触发操作，不属于默认工作流。
- 离线与只读：禁用外链导航，禁止加载远程资源，禁止修改图片文件。
- 大量图片：分页渲染，不一次性把全部 DOM 卡片插入页面。

## 路径和权限边界

EXE 只接受命令行传入的 `--study-root`、`--manifest`、`--images-root` 等参数。运行时校验：

- `manifest` 必须存在，且在 `study-root` 下。
- CLI 中必须至少包含一个 `--images-root`，并且规范化后的 CLI 图片根集合必须与 manifest `source_roots[].path` 集合完全一致；缺失、多余或不一致都视为授权失败。
- `source_path` 必须位于 CLI 显式授权且与 manifest 一致的图片根目录下；`thumbnail_path` 必须位于 `study-root/4.临时目录/中间索引/图片画廊/` 下。
- `shell.showItemInFolder` 只定位 manifest 中的本地文件，不执行脚本、不提升权限。
- 所有日志只写入 `4.临时目录/工具日志/` 或 `4.临时目录/中间索引/图片画廊/`。

Electron `main.js` 的授权模型示例：

```javascript
function argValues(name) {
  const values = [];
  for (let index = 0; index < process.argv.length; index += 1) {
    if (process.argv[index] === name && index + 1 < process.argv.length) {
      values.push(process.argv[index + 1]);
    }
  }
  return values;
}

function normalizeRoot(root) {
  return path.resolve(root);
}

function sameRootSet(left, right) {
  const normalizeForCompare = (value) => process.platform === "win32" ? value.toLowerCase() : value;
  const a = new Set(left.map((item) => normalizeForCompare(normalizeRoot(item))));
  const b = new Set(right.map((item) => normalizeForCompare(normalizeRoot(item))));
  return a.size === b.size && [...a].every((item) => b.has(item));
}

function resolveRuntime() {
  const studyRoot = normalizeRoot(argValue("--study-root") || "");
  const manifestPath = normalizeRoot(argValue("--manifest") || "");
  const cliImageRoots = argValues("--images-root").map(normalizeRoot);
  const manifest = JSON.parse(fs.readFileSync(manifestPath, "utf8"));
  const manifestImageRoots = (manifest.source_roots || []).map((root) => root.path).filter(Boolean);
  if (!sameRootSet(cliImageRoots, manifestImageRoots)) {
    throw new Error("manifest image roots do not match CLI --images-root values");
  }
  const galleryIndexRoot = path.resolve(studyRoot, "4.临时目录", "中间索引", "图片画廊");
  return {
    studyRoot,
    manifestPath,
    manifest,
    allowedImageRoots: cliImageRoots,
    allowedThumbnailRoot: galleryIndexRoot
  };
}
```

## 配置化覆盖范围

`references/image-gallery-viewer-config.json` 负责集中管理：

- 工具名、工具版本、EXE 相对路径、BAT 文件名。
- 默认图片根目录候选，例如 `1.分类资源/图片`。
- 支持扩展名，例如 `.png`、`.jpg`、`.jpeg`、`.bmp`、`.webp`、`.gif`、`.tga`。
- 缩略图尺寸、缩略图格式、透明背景棋盘格颜色。
- manifest 输出目录、缩略图目录、错误日志文件名。
- 默认排序、分页大小、分类推断规则。
- 状态枚举和最大错误记录数量。

禁止把某个游戏名、某个 study-root、某次导出路径、某个固定图片名写死在 Python、BAT 或 Electron 代码中。

## 设计模式适配

- **Manifest Contract**：Python 生成链路和 EXE 运行时只通过 manifest 交互，避免双端各自扫描造成行为不一致。
- **Strategy**：图片根扫描、分类推断和缩略图生成按策略函数组织，后续可加入原始导出索引、分类资源目录或自定义图片根。
- **Adapter**：BAT 生成器把 study-root 与固定 EXE 之间的参数适配成 Windows 双击入口。
- **Fail Soft**：单张图片损坏或缩略图失败不阻塞整个画廊，错误进入 `errors.jsonl`，manifest summary 记录失败数量。
- **Configuration Object**：所有规则从 JSON 配置加载，再由公共模块做默认值校验和路径解析。

## 文档和流程迁移

需要同步更新以下默认流程描述：

- `SKILL.md`：`2.报告/` 允许 `打开图片画廊.bat` 作为图片画廊入口；脚本表加入新脚本；旧 `build_gallery_exe.ps1` 标为兼容工具。
- `references/directory-spec.md`：图片画廊入口从 `全量图片画廊.html` 改为 `打开图片画廊.bat`，manifest 和缩略图仍在 `4.临时目录`。
- `references/full-extraction-workflow.md`：默认命令改为 manifest + BAT；旧 HTML 命令移入兼容说明。
- `references/gamemaker-datawin-workflow.md`：GameMaker 分类与画廊阶段改为新客户端入口。
- `references/multi-agent-prompts.md`：相关角色不再要求 `build_full_image_gallery.py` 和每项目 `build_gallery_exe.ps1`，改为新 manifest/launcher。
- `references/tooling-manifest.json`：新增 `GameImageGallery` 固定工具记录。
- `test-prompts.json`：期望产物从 HTML/portable EXE 改为 BAT + manifest + 固定 EXE。

## 测试策略

- Python 单元测试覆盖配置加载、路径解析、中文路径、manifest schema、缩略图 PNG 输出、损坏图片失败记录、BAT 内容引号和 EXE 缺失提示。
- 静态模板测试覆盖 Electron 源码必须读取命令行 manifest、不能硬编码 `全量图片画廊.html`、必须包含本地路径白名单和禁用外链导航。
- 文档契约测试覆盖 `SKILL.md`、`directory-spec.md`、workflow 和 multi-agent prompt 中的新默认入口。
- 手工验收使用一个临时中文 study-root，生成 2 张图片和 1 张损坏文件，验证 BAT、manifest、缩略图和错误日志。
- 固定 EXE 验证是必达验收：如果 `built-in-tools/GameImageGallery_1.0.0/GameImageGallery.exe` 已存在，必须使用 `--self-test --study-root ... --manifest ... --images-root ...` 验证现有 EXE；如果不存在，必须运行 `scripts/build_image_gallery_viewer_exe.ps1` 构建后再验证。Node/npm 不可用且没有可验证的固定 EXE 时标记 BLOCKED。普通 Python 单元测试仍不依赖 Electron 安装，但不能替代固定 EXE 验收。

## 自审结论

- 通用架构：固定 EXE、manifest、缩略图缓存、BAT 启动器职责分离，不绑定某个游戏或某次导出；固定 EXE 的构建、存在验证和 self-test 是必达交付。
- 设计模式适配：Manifest Contract、Strategy、Adapter、Fail Soft 和 Configuration Object 均服务于可扩展图片来源和本地只读预览。
- 配置化覆盖范围：图片扩展名、默认路径、缩略图参数、输出文件名、状态枚举、分页排序、工具版本和图片根传递规则都进入配置或集中常量。
- 硬编码检查：只允许 BAT 在生成时写入当前本机 Skill EXE 绝对路径；代码中不得写死用户项目路径、游戏名或图片名。
- 默认流程替换：新客户端替代 HTML 画廊作为默认产物；旧 HTML 画廊保留为兼容工具，不再作为每次 GA 的默认步骤。
