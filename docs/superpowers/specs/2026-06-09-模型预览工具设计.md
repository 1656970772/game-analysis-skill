# GameAnalysis 模型预览工具设计

日期：2026-06-09

## 背景

GameAnalysis 现有图片画廊可以通过 HTML 和 Electron 壳查看导出的图片资源，但模型资源仍需要用户手动打开 Blender、F3D 或其他查看器。用户希望在每次 `game-analysis` 导出模型后，输出目录里有一个可双击入口，能直接浏览本次项目的全部模型，并且不在每次分析时重新打包或复制一个大型 EXE。

本设计将模型查看器沉淀为 skill 级固定工具：EXE 放在 `tools/` 下统一维护；每个 study-root 只生成轻量 BAT 启动器、manifest、缩略图和 FBX 预览缓存。

## 目标

- 在 `game-analysis/built-in-tools/GameModelViewer_<version>/GameModelViewer.exe` 提供一个本地离线模型画廊工具。
- 在每个输出项目的 `2.报告/` 下生成 `打开模型预览.bat`，用户双击后直接打开本次项目的模型目录。
- 支持浏览 `1.分类资源/模型/` 下的所有 `.gltf`、`.glb`，并通过预转换缓存支持 `.fbx` 的预览。
- 底部展示模型缩略图条，支持点击切换、搜索、筛选、键盘切换、打开所在目录。
- 模型索引、错误信息、缩略图、预览转换缓存写入 `4.临时目录/中间索引/模型预览/`，不污染 `1.分类资源/` 和 `2.报告/`。
- 遵守 GameAnalysis 的本地授权边界：只读取用户授权导出的 study-root，不上传模型、不联网、不修改源游戏目录。

## 非目标

- 第一版不做模型编辑、导出改写、材质重绑定写回、动画剪辑重定向或批量修复。
- 第一版不直接支持所有 3D 格式；OBJ、DAE、STL、USD 等只作为后续扩展。
- 第一版不把 EXE 复制到每个输出项目，也不在每次 GameAnalysis 执行时重新 build EXE。
- 第一版不依赖外部在线 viewer，不要求用户启动浏览器或本地 HTTP server。

## 推荐方案

采用“固定工具 EXE + 项目 BAT 启动器 + 项目 manifest”的架构。

```text
game-analysis/
  tools/
    GameModelViewer_1.0.0/
      GameModelViewer.exe
      LICENSES/
      VERSION.txt
  assets/
    model-gallery-viewer-src/        # EXE 源模板和构建输入
  scripts/
    build_model_gallery_manifest.py
    render_model_thumbnails_blender.py
    create_model_viewer_launcher.py
    build_model_viewer_tool.ps1      # 仅维护工具时运行，不在每次分析中运行

<study-root>/
  1.分类资源/
    模型/
      <模型名>/
        *.gltf | *.glb | *.fbx
        textures/
  2.报告/
    打开模型预览.bat
  4.临时目录/
    中间索引/
      模型预览/
        manifest.json
        thumbs/
        preview-cache/
        errors.jsonl
```

### 为什么这样做

- 工具只构建一次，避免每次分析项目都产生一份几十到上百 MB 的 EXE。
- BAT 很小，适合放进 `2.报告/` 作为用户入口，同时符合“报告目录只放阅读/入口产物”的规则。
- manifest 和缩略图属于中间索引，保存在 `4.临时目录/`，不会污染最终分类资源。
- EXE 通过命令行参数接收路径，不写死项目名、游戏名或某次任务的目录。

## 启动器设计

每次 GameAnalysis 发现 `1.分类资源/模型/` 存在模型文件时，生成：

```text
<study-root>/2.报告/打开模型预览.bat
```

BAT 只负责定位固定 EXE 并传入本次项目路径。命令行参数为：

```text
GameModelViewer.exe ^
  --study-root "<study-root>" ^
  --models-dir "<study-root>\1.分类资源\模型" ^
  --manifest "<study-root>\4.临时目录\中间索引\模型预览\manifest.json" ^
  --thumbs-dir "<study-root>\4.临时目录\中间索引\模型预览\thumbs" ^
  --preview-cache-dir "<study-root>\4.临时目录\中间索引\模型预览\preview-cache"
```

EXE 定位优先级：

1. `GAME_ANALYSIS_MODEL_VIEWER` 环境变量指向的 EXE。
2. `GAME_ANALYSIS_SKILL_ROOT\built-in-tools\GameModelViewer_<version>\GameModelViewer.exe`。
3. 生成 BAT 时写入的当前 skill 绝对路径。

如果 EXE 不存在，BAT 显示中文错误提示并暂停，提示用户检查 skill 的 `built-in-tools/GameModelViewer_<version>/` 是否存在。

## 模型索引设计

`build_model_gallery_manifest.py` 扫描 `models-dir`，生成 `manifest.json`。扫描规则配置化，不在代码中写死单个项目名称或某次任务路径。

manifest 结构：

```json
{
  "schema_version": 1,
  "generated_at": "2026-06-09T00:00:00+08:00",
  "study_root": "E:\\AI_Projects\\GameAnalysis\\ExampleGame",
  "models_dir": "E:\\AI_Projects\\GameAnalysis\\ExampleGame\\1.分类资源\\模型",
  "viewer": {
    "required_tool": "GameModelViewer",
    "minimum_version": "1.0.0"
  },
  "items": [
    {
      "id": "stable-hash",
      "name": "角色_主角",
      "source_format": "gltf",
      "source_path": "E:\\...\\1.分类资源\\模型\\角色_主角\\角色_主角.gltf",
      "preview_path": "E:\\...\\1.分类资源\\模型\\角色_主角\\角色_主角.gltf",
      "thumbnail_path": "E:\\...\\4.临时目录\\中间索引\\模型预览\\thumbs\\stable-hash.png",
      "model_dir": "E:\\...\\1.分类资源\\模型\\角色_主角",
      "texture_status": "bound",
      "material_status": "verified",
      "preview_status": "ready",
      "tags": ["gltf", "has_texture"],
      "stats": {
        "mesh_count": 1,
        "material_count": 2,
        "animation_count": 0
      },
      "errors": []
    }
  ]
}
```

字段要求：

- `source_path` 永远指向真实导出的原始模型文件。
- `preview_path` 指向 EXE 实际加载的文件；glTF/GLB 通常等于 `source_path`，FBX 指向 `preview-cache/*.preview.glb`。
- `texture_status` 使用枚举：`bound`、`missing`、`same_name_candidate`、`none`、`unknown`。
- `preview_status` 使用枚举：`ready`、`converted`、`failed`、`unsupported`。
- `errors` 只记录诊断摘要，不写入大段堆栈或敏感环境信息。

## EXE 客户端设计

EXE 使用 Electron + Three.js。主进程负责命令行参数、路径白名单、右键打开目录；渲染进程负责 UI 和 WebGL 预览。

核心模块：

- `ArgumentResolver`：解析 `--study-root`、`--models-dir`、`--manifest` 等参数，并校验路径必须位于 study-root 内或明确允许的 skill `built-in-tools` 内。
- `ManifestLoader`：读取 manifest；不存在或过期时提示用户重新生成索引，不在 EXE 中私自递归扫描任意磁盘。
- `AssetProtocol`：把 study-root 内模型、贴图、缩略图映射为只读本地资源 URL，解决 glTF 外挂 `.bin` 和贴图加载问题。
- `ModelViewer`：Three.js 场景、GLTFLoader、OrbitControls、自动取景、灯光、网格地面、错误占位。
- `ModelStrip`：底部缩略图条，支持当前项高亮、左右切换、懒加载。
- `ModelInspector`：显示模型名、格式、材质状态、贴图状态、路径、统计信息、错误信息。
- `ExplorerActions`：打开模型目录、复制路径、打开缩略图目录。

UI 采用工具型布局，不做营销式首页：打开即进入模型浏览界面。

## 缩略图与 FBX 预转换

缩略图由 `render_model_thumbnails_blender.py` 生成，优先使用 Blender CLI。规则：

- `.gltf/.glb` 直接渲染缩略图。
- `.fbx` 先通过 Blender 导入，再导出为 `preview-cache/<id>.preview.glb`，同时渲染缩略图。
- 转换失败不阻塞其他模型，写入 `errors.jsonl` 并在 manifest 中标记 `preview_status: failed`。
- 缩略图正式产物为 `.png`，保存在 `4.临时目录/中间索引/模型预览/thumbs/`。
- 缩略图文件名使用稳定 hash，避免中文路径、超长文件名和重复模型名导致冲突。

如果 Blender 不可用：

- manifest 仍生成。
- `.gltf/.glb` 可在 EXE 中直接预览。
- `.fbx` 标记为 `unsupported` 或 `needs_blender_conversion`。
- 缩略图使用客户端占位图，不生成伪缩略图。

## 配置化要求

新增配置文件建议为：

```text
references/model-viewer-gallery-config.json
```

配置项包括：

- 支持的源格式和优先级。
- 是否启用 FBX 预转换。
- 缩略图尺寸、相机角度、背景色、灯光配置。
- 单模型最大文件大小、单次批处理最大数量。
- 材质状态标签映射和筛选标签。
- BAT 文件名、EXE 工具名、工具版本。

所有模型格式、路径候选、状态枚举、缩略图参数都通过配置或常量表集中管理；禁止把某个游戏、某个模型名、某次导出路径写死到脚本或客户端中。

## 错误处理

- 模型目录不存在：BAT/EXE 显示“本项目没有可预览模型”，不抛出崩溃窗口。
- manifest 不存在：EXE 显示生成命令提示；GameAnalysis 正常流程中应提前生成。
- 单个模型加载失败：当前视口显示失败原因，底部缩略图保留，用户可切换其他模型。
- 外挂贴图或 `.bin` 缺失：模型项显示 `missing` 状态，不尝试联网查找。
- 路径越界：EXE 拒绝加载 study-root 外的模型路径，除非该路径是传参指定的 skill 工具路径。
- 中文、空格、长路径：脚本使用 `-LiteralPath`、UTF-8、稳定 hash 和 JSON 转义；BAT 使用引号包裹参数。

## 安全与边界

- EXE 默认离线运行，不主动访问网络。
- EXE 只读访问 study-root；打开目录只调用系统资源管理器。
- 不上传、不压缩、不分发第三方模型资源。
- `2.报告/打开模型预览.bat` 是本地入口，不作为可跨机器分发的独立包承诺。
- `built-in-tools/GameModelViewer_<version>/` 作为本机工具沉淀，更新 `references/tooling-manifest.json` 记录版本、路径、来源、许可证和用途。

## 流程集成

GameAnalysis 在模型导出和分类完成后执行：

1. 检查 `1.分类资源/模型/` 是否存在模型文件。
2. 运行 `build_model_gallery_manifest.py` 生成或刷新 manifest。
3. 如果 Blender 可用，运行 `render_model_thumbnails_blender.py` 生成缩略图和 FBX 预览缓存。
4. 运行 `create_model_viewer_launcher.py` 在 `2.报告/` 生成 `打开模型预览.bat`。
5. 在 `2.报告/00_研究总览.md` 写入模型预览入口、模型数量、失败数量和工具状态。
6. 最终完成前检查 BAT、manifest、缩略图目录和错误日志是否存在且路径有效。

## 验证计划

单元测试：

- manifest 扫描中文路径、空格路径、重复模型名、空模型目录。
- `.gltf/.glb/.fbx` 格式识别和优先级选择。
- 路径越界检测、相对路径规范化、hash 稳定性。
- BAT 生成内容包含正确引号、参数和错误提示。

集成测试：

- 用小型 glTF 样本验证 EXE 可加载模型、贴图、外挂 `.bin`。
- 用中文 study-root 验证 BAT 双击路径传参。
- 用缺失贴图样本验证错误状态不阻塞其他模型。
- 用 FBX 样本验证 Blender 预转换和缩略图生成；Blender 缺失时验证降级路径。

人工验收：

- 双击 `2.报告/打开模型预览.bat` 能打开 viewer。
- 底部缩略图可切换模型。
- Orbit 旋转、缩放、平移正常。
- 右键或按钮能打开模型所在目录。
- 断网状态下仍能运行。
- GameAnalysis 再次执行不会重新 build EXE，也不会复制 EXE 到项目目录。

## 实施计划审查要点

- 通用架构：EXE、manifest、缩略图、BAT 启动器各自职责清晰，通过命令行和 JSON 交互，不绑定某个游戏项目。
- 设计模式适配：客户端使用参数解析、manifest repository、只读 asset protocol、viewer component、action service 等可替换边界；脚本使用扫描器、渲染器、启动器生成器分离。
- 配置化覆盖范围：格式支持、路径候选、状态枚举、缩略图渲染参数、工具版本、BAT 名称和批处理限制都必须配置化或集中常量化。
- 硬编码检查：不得写死某个 study-root、模型名、游戏名、绝对输出路径或一次性工具路径；BAT 中的 skill EXE 绝对路径只作为本机生成时的 fallback。

## 已采纳决策

- 第一版只承诺 `.gltf/.glb` 直接预览，`.fbx` 通过 Blender 预转换后预览。
- BAT 文件名固定为 `打开模型预览.bat`。
- 固定 EXE 的初始版本目录使用 `built-in-tools/GameModelViewer_1.0.0/`。
